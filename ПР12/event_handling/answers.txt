Ответы на вопросы по практической работе 12

1. В чем разница между event.preventDefault() и event.stopPropagation()? В каких ситуациях используется каждый метод?
event.preventDefault() отменяет стандартное поведение браузера для этого элемента (например, переход по ссылке или перезагрузку страницы при отправке формы). Используется, когда надо обработать действие своим скриптом.
event.stopPropagation() останавливает "всплытие" события. Событие происходит на дочернем элементе, но не передается его родителям. Используется, чтобы клик по кнопке внутри карточки не вызывал клик по самой карточке.

2. Как работает делегирование событий и какие преимущества оно даёт по сравнению с назначением обработчиков на отдельные элементы?
Делегирование - приём, при котором обработчик назначается на родительский элемент. Когда событие происходит на дочернем элементе, оно "всплывает" до родителя, и обработчик срабатывает (используя event.target для определения конкретного элемента).
Преимущества: работает для динамически добавляемых элементов, экономит память (один обработчик вместо сотни) и упрощает код.

3. Какие фазы жизненного цикла события существуют в JavaScript (capturing, target, bubbling) и как они влияют на порядок выполнения обработчиков?
   3.1 Фаза перехвата (Capturing) - событие идет от window вниз к целевому элементу.
   3.2 Целевая фаза (Target) - событие достигло элемента, на котором произошло.
   3.3 Фаза всплытия (Bubbling) - событие поднимается от целевого элемента обратно вверх к window.
   3.4 По умолчанию обработчики срабатывают на фазе всплытия. Если передать третьим аргументом true в addEventListener, обработчик сработает на фазе перехвата (сработает раньше).

4. В чем разница между event.target и event.currentTarget? Когда следует использовать каждый из них?
event.target - элемент, на котором непосредственно произошло событие (например, конкретная кнопка или иконка внутри кнопки).
event.currentTarget - элемент, к которому привязан сам обработчик события (например, родительский div, если используется делегирование).
При делегировании нужно смотреть на event.target, чтобы понять, куда именно кликнул пользователь.

5. Как создать и запустить кастомное событие? Какие параметры можно передать в конструктор CustomEvent?
Создать: const event = new CustomEvent('имяСобытия', { detail: { ключ: 'значение' } });
Запустить: element.dispatchEvent(event);
В конструктор CustomEvent можно передать объект с параметрами: detail (данные, которые надо передать), bubbles (будет ли событие всплывать), cancelable (можно ли отменить).

6. Что такое debounce и throttle? В каких практических ситуациях их применение наиболее эффективно?
Debounce откладывает вызов функции до тех пор, пока не пройдет определенное время после последнего вызова. Эффективен для поиска при вводе (чтобы не отправлять запрос на каждую букву).
Throttle гарантирует, что функция будет вызываться не чаще, чем раз в указанный интервал времени. Эффективен для обработки скролла или изменения размера окна (чтобы не нагружать браузер).

7. Какие методы существуют для удаления обработчиков событий и почему важно удалять ненужные обработчики?
Удаление происходит через element.removeEventListener('click', functionName).
Важно удалять обработчики, когда элемент удаляется из DOM или когда обработчик больше не нужен, чтобы избежать "утечек памяти" (браузер продолжает хранить ссылки на функции и элементы).

8. Как обрабатывать ошибки загрузки ресурсов (изображений, скриптов) и какие события для этого используются?
Для изображений и скриптов используются события load (успешная загрузка) и error (ошибка загрузки). Можно повесить на элемент обработчик addEventListener('error', ...) и показать пользователю заглушку или сообщение об ошибке.

9. В чем разница между addEventListener и прямым назначением обработчиков через onclick, onkeydown и т.д.?
onclick может хранить только один обработчик (если назначить второй, он перезапишет первый).
addEventListener позволяет назначить сколько угодно обработчиков на одно событие. Также addEventListener позволяет управлять фазами (всплытие/перехват) и легко удалять обработчики.

10. Как оптимизировать производительность при работе с большим количеством событий? Какие лучшие практики существуют?
    1) Использовать делегирование событий вместо назначения обработчиков на каждый элемент.
    2) Применять debounce и throttle для частых событий (mousemove, scroll, input).
    3) Удалять обработчики (removeEventListener), когда они больше не нужны (например, при удалении элемента из DOM).
    4) Использовать пассивные слушатели (addEventListener('scroll', fn, { passive: true })), чтобы не блокировать прокрутку.
