Ответы на вопросы по практической работе 13

1. В чём разница между Fetch API и XMLHttpRequest? Какие преимущества предоставляет Fetch API?
Fetch API - современный стандарт, основанный на промисах (Promises), что делает код более чистым и удобным для чтения (позволяет использовать async/await).
XMLHttpRequest (XHR) - более старый API на основе колбэков. Fetch имеет более простой и гибкий синтаксис, но XHR до сих пор используется для отслеживания прогресса загрузки файлов (события upload.onprogress).

2. Как обрабатываются ошибки в Fetch API и почему ответ с HTTP статусом 404 не вызывает reject промиса?
Промис в Fetch API отклоняется (переходит в состояние reject) только в случае сетевых ошибок (например, нет подключения к интернету или DNS-ошибка). Если сервер отвечает статусом 404 или 500, промис успешно резолвится, но свойство response.ok будет равно false. Разработчик должен сам проверять response.ok и выбрасывать ошибку вручную.

3. Какие методы HTTP поддерживает Fetch API и в каких случаях используется каждый из них?
   • GET (получение данных),
   • POST (создание новых данных),
   • PUT (полное обновление существующих данных),
   • PATCH (частичное обновление),
   • DELETE (удаление), HEAD (запрос только заголовков),
   • OPTIONS (получение информации о поддерживаемых методах).

4. Как работать с заголовками запроса и ответа в Fetch API? Приведите примеры полезных заголовков.
В запросе заголовки передаются в объекте options (свойство headers). В ответе они доступны через response.headers (объект Headers).
Полезные заголовки:
   • Content-Type (формат данных),
   • Authorization (токены доступа),
   • Accept (какие форматы данных ожидает клиент),
   • Cache-Control (управление кэшированием).

5. В чем разница между PUT и PATCH запросами и когда следует использовать каждый метод?
PUT полностью заменяет ресурс. Если вы не передадите какое-то поле, сервер может удалить его или установить в null.
PATCH обновляет только те поля, которые переданы в запросе.
Используется PUT, когда нужно сохранить всю сущность целиком, и PATCH - для изменения одного конкретного свойства (например, только аватара).

6. Как реализовать авторизацию в Fetch API (Basic Auth, Bearer Token, OAuth2)?
Авторизация реализуется через заголовок Authorization.
   • Для Basic Auth: 'Authorization': 'Basic ' + btoa('login:password').
   • Для Bearer Token: 'Authorization': 'Bearer <токен>'.
   • OAuth2 использует Bearer Token после получения его от сервера авторизации.

7. Какие способы отмены запросов существуют в Fetch API и когда их следует использовать?
Отмена выполняется с помощью AbortController. Создается экземпляр контроллера, его свойство signal передается в fetch. Затем вызывается controller.abort(). Используется, когда пользователь уходит со страницы или когда запрос выполняется слишком долго (таймауты).

8. Как работать с разными форматами данных (JSON, FormData, Blob, ArrayBuffer) в Fetch API?
   • JSON: response.json(),
   • FormData: отправляется как есть (fetch сам ставит нужный Content-Type),
   • Blob: response.blob() (для файлов/картинок),
   • ArrayBuffer: response.arrayBuffer() (для бинарных данных низкого уровня).

9. Как оптимизировать производительность при работе с множественными запросами (параллельное выполнение, кэширование)?
   • Использовать Promise.all() для параллельной загрузки независимых данных.
   • Применять кэширование (сохранять результаты в Map с TTL).
   • Использовать отмену лишних запросов (AbortController), если пользователь быстро переключается между вкладками.

10. Какие лучшие практики существуют для работы с Fetch API в production приложениях?
   • Всегда проверять response.ok.
   • Использовать try/catch для обработки сетевых сбоев.
   • Выносить базовый URL в константы.
   • Использовать AbortController для таймаутов.
   • Внедрять кэширование для статических данных.
   • Использовать заголовок Content-Type при отправке тела запроса.
