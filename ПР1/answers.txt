Ответы на вопросы
1. Какие три основные области работы с файлами в Git (рабочая папка, индекс, репозиторий) и чем они отличаются?
Рабочая папка - каталог на компьютере, где находятся файлы проекта, которые можно просматривать, редактировать и в целом работать. Git видит изменения, но ещё не сохранил их в свою историю. В ней показывается текущее состояние файлов: неотслеживаемый или отслеживаемый (неизменённый или изменённый).
Индекс - промежуточная область (черновик), в которой находятся файлы после git add, но до git commit. После git add состояние файла становится Подготовленный (Staged).
Репозиторий - база данных Git, где хранятся коммиты и вся история изменений. Файлы становятся зафиксированными.

2. Что происходит при выполнении команд:
    git add - копирует текущее состояние указанного файла (файлов) в индекс.
    git commit - создаёт новый коммит из того, что было в индексе; сохраняет изменения в репозиторий.
    git push - отправляет локальные коммиты на удалённый репозиторий.

3. Почему важно писать информативные сообщения к коммитам а не просто "исправление" или "update"?
Чтобы можно было легко понять, что именно было сделано с файлом (изменено, добалено).

4. Чем отличается git add имя_файла от git add .? В каких случаях лучше использовать каждый вариант?
git add имя_файла добавляет конкретный файл (или файлы, если имена указаны через пробел). Лучше использовать, когда надо работать точечно или разбить файлы на блоки для коммитов.
git add . добавляет все файлы разом (кроме тех, что в .gitignore). Лучше использовать, когда уверен, что все файлы относятся к одной теме (смысловому блоку).

5. Что показывает команда git status и как меняется ее вывод на разных этапах работы?
git status показывает текущее состояние рабочей папке и индексов
Если использовать команду после инициализации репозитория, то будет сообщение:
"On branch master

No commits yet

nothing to commit (create/copy files and use "git add" to track)"

Если использовать после создания файла, то будет:
"On branch master

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        main.txt

nothing added to commit but untracked files present (use "git add" to track)"

Если использовать после git add:
"On branch master
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   main.txt
"

Если какой-то файл только создан, а другой был изменён:
"On branch master
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   main.txt

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        README.md

no changes added to commit (use "git add" and/or "git commit -a")
"

Если изменения были закоммичены:
"On branch main
Your branch is ahead of 'origin/main' by 1 commit.
  (use "git push" to publish your local commits)

no changes added to commit (use "git add" and/or "git commit -a")
"

6. Для чего нужна команда git remote add origin URL и что означает слово "origin"?
Данная команда создаёт связь между локальным репозиторием и удалённым.
add - добавить, remote - удалённый репозиторий, origin - имя, которое вы даёте этому удалённому репозиторию, URL - его адрес.

7. Зачем нужен флаг -u в команде git push -u origin main при первой отправке изменений?
Флаг -u (или --set-upstream) связывает вашу локальную ветку main с удалённой веткой origin/main. После этого Git запоминает эту связь.

8. Что такое ветка (branch) по умолчанию и какая у вас создалась (main или master)? Почему это важно?
Ветка по умолчанию - ветка, в которую попадают коммиты, если вы не создали другую, и которая считается главной в репозитории.
По умолчания в локальном репозитории создалать master ветка.
Имя ветки по умолчанию влияет на команды. Если клонируется репозиторий, где основная ветка main, а локально master, могут возникнуть путаницы при push/pull.

9. Как просмотреть историю коммитов и какую информацию о каждом коммите вы видите?
Посмотреть историю коммитов можно через git log
О каждом коммите можно посмотреть: хеш коммита (30068f3b3f1dd455094ba9b6a385d8883371f38c (HEAD -> master)), имя и почту автора (SergeySPK <shamanidisergo@gmail.com>), дату отправки (Wed Sep 16 08:52:17 2026 +0500), текст коммита (Добавлены изменения в main.txt и создан README.md)

10. Что произойдет, если сделать изменения в файле, но не выполнить git add перед git commit?
Изменения не попадут в коммит.
