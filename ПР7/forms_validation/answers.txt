Ответы на вопросы по практической работе 7

1. Какие HTML5-атрибуты используются для клиентской валидации и какую функциональность они предоставляют?
HTML5 предоставляет встроенные атрибуты для валидации без JavaScript: required (обязательное поле), minlength/maxlength (минимальная/максимальная длина текста), min/max (границы для чисел и дат), pattern (регулярное выражение), type (email, tel, url, number и др. - проверяет формат). Также step для чисел, accept для файлов. Браузер автоматически проверяет эти атрибуты при отправке формы и показывает сообщения об ошибках. Можно стилизовать состояния через псевдоклассы :valid и :invalid.
Например: <input type="email" required minlength="5" pattern=".+@.+\..+">

2. В чем разница между novalidate атрибутом формы и отключением валидации через JavaScript?
novalidate - HTML-атрибут, который полностью отключает встроенную браузерную валидацию при отправке формы. Браузер не блокирует отправку и не показывает свои сообщения. Если novalidate нет, браузер сам проверяет поля и останавливает отправку при ошибках.
Отключение валидации через JavaScript - это перехват события submit, вызов preventDefault() и ручная проверка полей. При этом встроенная валидация может продолжать работать (если не установлен novalidate), но мы её игнорируем.
Разница: novalidate убирает автоматическую проверку полностью, а JS-валидация может использовать API checkValidity(), но не показывает встроенные сообщения.

3. Как правильно связать <label> с полем ввода и почему это важно для доступности?
Связь осуществляется двумя способами:
1) через атрибут for у <label>, значение которого равно id поля:
<label for="email">Email</label><input id="email">;
2) путём обёртывания input внутрь label:
<label>Email
  <input type="email">
</label>. Это важно для доступности: скринридеры озвучивают подпись при фокусе на поле, увеличивается кликабельная область (клик по тексту фокусирует поле), улучшается удобство для пользователей с ограниченными возможностями.

4. Какие типы полей input наиболее подходят для разных видов данных (email, телефон, пароль и т.д.)?
email - для электронной почты, браузер проверяет формат и на мобильных показывает клавиатуру с @. tel - для телефона, не проверяет формат, но вызывает цифровую клавиатуру. password - скрывает вводимые символы. number - для чисел, поддерживает min/max/step. date - для даты, вызывает календарь. url - для URL. search - для поиска. color, range, file и др. Использование правильного типа улучшает мобильный ввод и встроенную валидацию.

5. Как работает валидация с помощью pattern атрибута и в каких случаях его следует использовать?
pattern задаёт регулярное выражение, которому должно соответствовать значение поля. Если значение не соответствует, поле считается невалидным (validity.patternMismatch = true). Работает для текстовых полей (text, tel, email, password и др.). Следует использовать, когда нужна специфическая проверка формата: телефон, пароль с требованиями, почтовый индекс и т.п.
Пример: <input type="tel" pattern="\+7\s?\([0-9]{3}\)\s?[0-9]{3}-[0-9]{2}-[0-9]{2}">

6. Какие события JavaScript используются для реализации валидации в реальном времени и почему?
Основные события: input (при вводе символов), blur (при потере фокуса), change (при изменении значения для select, checkbox, radio), submit (при отправке формы). Для реального времени обычно используют input для сброса ошибки и blur для проверки после заполнения. Это даёт баланс: пользователь не видит ошибку во время набора, но получает обратную связь, когда заканчивает ввод.

7. Как обеспечить доступность сообщений об ошибках для пользователей скринридеров?
Нужно использовать aria-live="polite" или role="alert" для контейнера с сообщением об ошибке, чтобы скринридер автоматически озвучивал изменения. Связывать ошибку с полем через aria-describedby, указав id элемента ошибки. Для поля устанавливать aria-invalid="true" при ошибке. Сообщение должно быть текстовым и понятным.
Пример:
<input id="email" aria-describedby="emailError" aria-invalid="true">
<span id="emailError" role="alert">Введите корректный email</span>

8. В чем преимущества использования fieldset и legend для группировки полей формы?
fieldset группирует связанные поля (например, «Личная информация», «Безопасность»), legend даёт название группы. Преимущества: улучшают доступность - скринридеры озвучивают legend при переходе к полям внутри группы; создают семантическую структуру, упрощают стилизацию и логическую организацию формы. Особенно полезно для радио-групп и чекбоксов, где важно понимать общий контекст.

9. Как реализовать кастомную валидацию для сложных случаев (например, подтверждение пароля)?
Для подтверждения пароля нужно сравнивать значения двух полей. Реализуется через JavaScript: при вводе в confirmPassword проверяем равенство с password, если не равны - показываем ошибку. Можно использовать setCustomValidity() для интеграции с браузерной валидацией. Функция validatePasswordMatch() вызывается на input у confirmPassword и при submit.

10. Какие методы CSS используются для визуального отображения состояний валидности/невалидности полей?
Псевдоклассы :valid, :invalid, :required, :optional, :in-range, :out-of-range, :placeholder-shown. Комбинируя их, можно стилизовать границы, фон, тень. Например:
input:invalid:not(:focus):not(:placeholder-shown) { border-color: #e53e3e; }
input:valid:not(:focus) { border-color: #38a169; }
Также используется класс .error, добавляемый через JS, для более точного контроля (например, анимация shake). В примере стилей есть и псевдоклассы, и класс error с анимацией.
