Ответы на вопросы по практической работе 15

1. В чём разница между функциональными и классовыми компонентами в React? Когда следует использовать каждый тип?
Функциональные компоненты - обычные JS-функции, которые возвращают JSX. Они проще, короче и не используют `this`. В современном React (с появлением хуков в версии 16.8) функциональные компоненты могут делать всё то же самое, что и классовые (иметь состояние, эффекты).
Классовые компоненты пишутся через классы и наследуются от `React.Component`, используют методы ЖЦ (componentDidMount и т.д.). Сейчас рекомендуется использовать функциональные компоненты с хуками, так как они более лаконичны и лучше оптимизируются.

2. Что такое props и state? Как они отличаются и какие правила их использования?
Props (свойства) - данные, которые передаются от родительского компонента дочернему. Они доступны только для чтения (immutable). Ребёнок не может изменять props.
State (состояние) - внутренние данные компонента, которые он может изменять с помощью setState (в классах) или useState (в функциях). Изменение state приводит к перерисовке компонента.

3. Как работает поднятие состояния (lifting state up) и в каких ситуациях это необходимо?
Если двум компонентам нужно синхронизировать данные (например, один компонент изменяет значение, а другой отображает), состояние переносится в их ближайшего общего родителя. Родитель передаёт данные вниз через props и передаёт функции-колбэки для изменения этих данных. Это необходимо для создания единого источника истины (single source of truth).

4. Какие методы жизненного цикла классовых компонентов вы знаете и для чего они используются?
Основные:
   • componentDidMount (вызывается после первого рендера - идеально для запросов к API),
   • componentDidUpdate (вызывается после обновления - для реакции на изменение props/state),
   • componentWillUnmount (вызывается перед удалением компонента - для очистки таймеров и отписки от событий).

5. Как работают хуки useState и useEffect? Какие правила использования хуков существуют?
useState принимает начальное значение и возвращает массив из двух элементов: текущее состояние и функцию для его обновления.
useEffect принимает функцию-эффект и массив зависимостей. Эффект выполняется после рендера.
Правила хуков:
   1) Вызывать хуки только на верхнем уровне (не внутри условий или циклов).
   2) Вызывать хуки только из React-функций или кастомных хуков.

6. Что такое ключи (keys) в React и почему они важны при рендеринге списков?
Keys - специальные строковые атрибуты (key), которые нужно передавать элементам при рендере массива.
Они помогают React идентифицировать, какие элементы изменились, были добавлены или удалены. Без ключей React не может эффективно обновлять список и может перерисовывать весь список целиком, что бьет по производительности.

7. Как обрабатывать события в React и чем это отличается от нативного JavaScript?
В обработчик передается не строка, а функция. React использует синтетические события (SyntheticEvent) - кросс-браузерная обёртка над нативными событиями для одинаковой работы во всех браузерах. По умолчанию React использует делегирование событий (вешает обработчик на корень документа).

8. Что такое управляемые и неуправляемые компоненты? В чем их разница?
Управляемый компонент (Controlled) - форма, значения полей которой управляются состоянием React (state). Каждое изменение ввода вызывает onChange, обновляет state, и новое значение передаётся обратно в input.
Неуправляемый (Uncontrolled) - данные хранятся в самом DOM, а не в state (доступ к ним получают через useRef). Управляемые компоненты предпочтительнее для валидации.

9. Как работает контекст (Context) в React и когда его следует использовать?
Контекст позволяет передавать данные через дерево компонентов без необходимости передавать props вручную на каждом уровне (решает проблему "prop drilling").
Используется для глобальных данных, таких как текущая тема (светлая/темная), данные авторизованного пользователя, языковые настройки.

10. Какие преимущества предоставляют кастомные хуки и как создавать собственные хуки?
Кастомные хуки позволяют выносить повторяющуюся логику (например, логику работы с формами, fetch-запросами или localStorage) в отдельные функции. Это делает код чище и избавляет от дублирования.
Кастомный хук - обычная функция, название которой начинается с "use", и которая внутри себя вызывает другие хуки (useState, useEffect).
