Ответы на вопросы по практической работе 8

1. Какие инструменты графического редактора наиболее полезны для извлечения информации о размерах, цветах и шрифтах?
В Figma основными инструментами являются панель свойств (Design Panel), которая показывает размеры, отступы и параметры типографики. Также крайне полезен режим разработчика (Dev Mode), который выдает точные CSS-значения без округления. Дополнительно можно использовать плагины для автоматической генерации спецификаций.

2. Как правильно организовать структуру CSS-переменных на основе данных из макета?
Рекомендуется использовать трехуровневую систему: примитивные токены (сырые значения вроде #ff5545), семантические токены (описывают роль, например --color-primary) и компонентные токены (для конкретных кнопок или блоков). Все повторяющиеся цвета, отступы и размеры шрифтов обязательно выносятся в :root.

3. Какие метрики из макета наиболее критичны для точной верстки (размеры, отступы, шрифты)?
Наиболее критичны размеры шрифтов и межстрочные интервалы (line-height), так как они формируют визуальную иерархию. Также важны отступы (padding/margin) для создания правильного "воздуха" и ширина контейнера, задающая каркас страницы.

4. Как определить систему сетки, используемую в макете и перенести ее в CSS Grid или Flexbox?
В Figma сетка видна в режиме Layout Grid (количество колонок, ширина желоба, отступы по краям). Для переноса в CSS используются Flexbox для одномерных сеток (навигация, футер) и CSS Grid для двумерных (галереи, карточки), с указанием grid-template-columns и gap.

5. Какие сложности возникают при переносе типографии из графического макета в веб-страницу?
Основные сложности связаны с различиями в рендеринге шрифтов разными браузерами, а также с отсутствием нужного шрифта в веб-доступе (требуется подключение через @font-face). Кроме того, дизайнеры иногда используют дробные значения размеров (например, 14.3px), которые приходится адаптировать под пиксели или rem.

6. Как обрабатывать адаптивность, когда в макете представлен только десктопный вариант?
Необходимо самостоятельно продумать поведение элементов на разных экранах. Используются медиа-запросы (@media), гибкие единицы измерения (%, vw, rem), свойство flex-wrap, а также перестройка многоколоночных сеток в одноколоночные для мобильных устройств.

7. Какие инструменты браузера помогают сравнивать сверстанную страницу с оригинальным макетом?
Встроенные инструменты разработчика (DevTools), в частности вкладка Elements для проверки вычисленных стилей. Также очень помогают расширения для наложения макета (например, PerfectPixel), позволяющие совместить полупрозрачную картинку макета с готовой страницей.

8. Как правильно экспортировать изображения из графического редактора для веб-использования?
Для фотографий лучше использовать WebP или JPEG (с оптимизацией), для иконок и логотипов - SVG, для картинок с прозрачностью - PNG. Важно экспортировать изображения в нужном разрешении (1x, 2x для Retina-экранов) и предварительно сжимать их для уменьшения веса страницы.

9. Что делать, если в макете используются шрифты, которых нет в веб-доступе?
Если есть лицензия - подключить через @font-face. Если нет - подобрать похожий бесплатный шрифт (например, из Google Fonts) или связаться с дизайнером для замены. В CSS обязательно указывать fallback-стек из системных шрифтов на случай, если основной не загрузится.

10. Какие методологии помогают поддерживать соответствие между макетом и кодом при дальнейших изменениях?
Дизайн-токены (единый источник правды для цветов и отступов), компонентный подход (четкое соответствие компонентов Figma и кода), а также инструменты вроде Figma Dev Mode и Code Connect, которые связывают слои макета с компонентами в репозитории.
