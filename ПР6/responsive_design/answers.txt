Ответы на вопросы по практической работе 6

1. Что такое Viewport meta tag и почему он важен для адаптивного дизайна?
Viewport meta tag - мета-тег, который сообщает браузеру, как масштабировать страницу на разных устройствах. Синтаксис: <meta name="viewport" content="width=device-width, initial-scale=1.0">.
Без него мобильные браузеры открывают страницу в виртуальном окне ~980px и уменьшают её, из-за чего текст становится мелким, медиа-запросы не срабатывают корректно, а верстка выглядит как уменьшенная десктопная. С ним ширина viewport равна ширине экрана устройства, а начальный масштаб - 1:1.

2. Какие основные подходы к созданию адаптивных макетов вы использовали в работе (Fluid, Adaptive, Responsive)?
Fluid: резиновые контейнеры (width: 100%; max-width: 1200px), изображения (max-width: 100%; height: auto), относительные единицы (%, rem, vw).
Adaptive: явные брейкпоинты через @media для 1024px, 768px, 480px; grid переключается с 3 колонок на 2, затем на 1.
Responsive: сочетание fluid + adaptive + медиа-запросов + адаптивных изображений + clamp/vw. Именно этот подход итоговый.

3. Как работает Mobile First подход и в чем его преимущества перед Desktop First?
Mobile First - методология, при которой базовые стили пишутся для мобильных, а через @media (min-width: ...) добавляются стили для планшетов и десктопов.
Преимущества: проще код, быстрее загрузка на мобильных, меньше конфликтов в медиа-запросах, контент проектируется по приоритету, лучше SEO и Core Web Vitals.
Desktop First - обратный подход (max-width): базовые стили для десктопа, мобильные - переопределения. Рабочий, но чаще даёт громоздкий CSS.

4. Какие единицы измерения наиболее предпочтительны для адаптивной верстки и почему (%, rem, em, vw/vh)?
% - для ширин контейнеров, изображений, grid/flex-элементов.
rem - для шрифтов, отступов, размеров блоков; масштаб всей страницы меняется одной правкой html { font-size }.
em - для компонентов, зависящих от локального шрифта (кнопки).
vw/vh - проценты от viewport; удобно для hero-секций и крупных заголовков.
clamp(min, pref, max) - комбинирует min и max с «резиновым» значением.
px - только для границ, теней, мелких фиксированных деталей.

5. Как функция clamp() помогает создавать адаптивную типографику?
clamp(min, preferred, max) возвращает значение, которое не меньше min, не больше max и плавно меняется по preferred.
Пример: font-size: clamp(1.5rem, 5vw, 2.5rem); - на узких экранах шрифт не ниже 1.5rem, на широких не выше 2.5rem, между ними равен 5vw.
Плюсы: не нужны отдельные медиа-запросы, плавная адаптация без скачков, читаемость сохраняется на любом устройстве.

6. Какие основные брейкпоинты вы использовали и как определили эти значения?
1200px+ - десктоп, базовые стили, 3 колонки .features-grid.
1024px и меньше - планшет: max-width: 90%, 2 колонки, .content → column.
768px и меньше - мобильные: кнопка .nav-toggle, меню в dropdown, hero центрируется.
480px и меньше - маленькие: 1 колонка, уменьшенные шрифты, padding: 0 0.5rem.
Значения выбраны по типовым разрешениям устройств (iPad 768/1024, iPhone 375/414), статистике посещаемости и поведению контента. Брейкпоинты ставятся там, где макет «ломается», а не под конкретные модели.

7. Как медиа-запросы @media помогают создавать адаптивные стили? Приведите пример синтаксиса.
@media применяет стили только при выполнении условия (ширина, высота, ориентация, разрешение).
Синтаксис:
@media (max-width: 768px) {
    .nav-menu { display: none; }
    .nav-toggle { display: block; }
}
В работе: @media (max-width: 1024px), (max-width: 768px), (max-width: 480px).
Позволяют перестраивать grid/flex, скрывать/показывать элементы, менять шрифты и отступы, переопределять flex-direction.

8. В чем разница между max-width и min-width в медиа-запросах и когда использовать каждый?
max-width: «ширина экрана ≤ N» - подход Desktop First, стили применяются к этому размеру и меньше.
min-width: «ширина экрана ≥ N» - подход Mobile First, стили применяются к этому размеру и больше.
min-width используется в Mobile First (рекомендуется): базовые стили для мобильных, расширения по возрастанию.
max-width - в Desktop First или для точечной адаптации готового десктопного макета, как в этой работе. При max-width порядок запросов - от большего к меньшему.

9. Как сделать изображения адаптивными и какие CSS-свойства для этого используются?
Базовая адаптивность:
img { max-width: 100%; height: auto; }
Дополнительно: .responsive-img { width: 100%; height: auto; border-radius: 8px; margin: 1rem 0; }
Современный вариант: img { max-width: 100%; height: auto; display: block; }
Для разных разрешений: <picture> с <source media="..."> или srcset/sizes.
object-fit: cover / contain - для кадрирования внутри фиксированного контейнера.
Ключевые свойства: max-width, width, height: auto, object-fit, srcset/sizes, <picture>.

10. Какие инструменты браузера помогают тестировать и отлаживать адаптивный дизайн?
DevTools (F12) → Elements: просмотр CSS, индикация активных @media.
Device Toolbar (Ctrl+Shift+M): режим адаптивного дизайна, эмуляция устройств, ручное задание размеров, поворот экрана.
Network: проверка загрузки изображений, эмуляция Slow 3G, проверка srcset/sizes.
Lighthouse: аудит адаптивности, производительности, SEO, mobile-friendly.
CSS Overview: сводка по цветам, шрифтам, медиа-запросам.
Rulers / Grid / Flex overlays: визуализация grid- и flex-контейнеров.
Внешние: Responsively App, BrowserStack, LambdaTest.
Проверка на реальных устройствах: chrome://inspect (Android), Safari → Develop (iOS).
